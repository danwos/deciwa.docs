Web script¶

Technical details: Web script.

Review any website – built with Astro, Hugo, WordPress or by hand – without changing its build. One line in the page is enough:

<script src="https://deciwa.danwos.dev/js/0.2/deciwa.js" defer></script>

The deciwa button appears at the bottom right of every page that loads the script. deciwa finds the elements of the page by itself – sections, paragraphs, list items, table rows, code blocks and pictures – and shows the same review UI as the Sphinx integration.

What you need to know – nothing¶

Without any setting

Elements

found in <main>, otherwise <article>, otherwise <body>; navigation, header, footer and forms are left out

Feedback is stored

in your browser, per website; Export hands it over as one file

A page is identified by

its address, e.g. danwos.dev/services/

In review mode a click selects an element, also when the element is a link or contains one – a card that is one big link opens the review card. Ctrl/Cmd + click follows the link; navigation outside the content keeps working.

Optional settings¶

All settings are attributes on the script tag. Leave them out until you need them.

Attribute

Effect

data-root="main"

review only this part of the page (a CSS selector)

data-ignore=".cookie-banner, aside"

leave these parts out

data-activate="param"

show deciwa only after ?deciwa was in the address – for public sites whose visitors must not see it; it stays on in that tab until ?deciwa=off

data-server="http://127.0.0.1:4337"

store feedback with a deciwa server instead of the browser (later, see Roadmap)

A page can name its source file, so the AI knows which file to change:

<meta name="deciwa-source" content="src/content/pages/services.md">

Instead of tagging every page, the repository can map addresses to files once in .deciwa/config.toml (File format). Both are optional: without them every page is kept under its address, and nothing is lost when a mapping is added later.

From the browser to the repository¶

  1. Review the pages; feedback stays in the browser.

  2. Export in the panel saves one JSON file. It holds the feedback and the elements of every page this browser has seen.

  3. deciwa init once in the website’s repository, then deciwa import export.json. It replaces the review data of the pages in the file and leaves everything else in .deciwa/ alone – an older file is refused unless --force is given.

  4. deciwa todo lists the open jobs for the AI or a developer, with the source file and the address of the page:

$ deciwa import deciwa-review-20261020.json
replaced: 2 annotations in 2 sources
  mapped to src/content/tools/de/monsterbrain.mdx
$ deciwa todo
yu6xkuap  note      src/content/tools/de/monsterbrain.mdx (danwos.dev/de/tools/monsterbrain)  html:paragraph:monsterbrain/Warum monsterbrain#2
          “Satz ist zu lang, bitte in zwei Sätze teilen.”

Mapping pages to files (optional)¶

Without a mapping a page is kept under its address, and deciwa todo names the address only. Rules in .deciwa/config.toml tell deciwa which file a page comes from; a star stands for any part of the address and is put into the file name in the same order:

[web]
sources = [
  { url = "/*/tools/*", file = "src/content/tools/*/*.mdx" },
  { url = "/*/tools/*", file = "src/content/tools/*/*.md" },
]

The first rule whose file exists wins, so /de/tools/monsterbrain becomes src/content/tools/de/monsterbrain.mdx. A rule added later moves the feedback that was kept under the address: deciwa remap.

The Chrome extension will use the same script, so it also works on pages that cannot be changed.
