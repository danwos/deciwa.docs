Technical overview¶

Status: draft

How the next version (0.1) is built – updated for every version. Proposals by Claude, 2026-10-19; nothing on these pages is binding until Daniel approves it. Questions that block work are collected in Open questions.

Goal¶

Build release 0.1 (Roadmap): the CLI with the open file format, the adapters Markdown, rST/Sphinx-Needs and plain text, and the agent skills deciwa-work and deciwa-ask – good enough that Daniel uses deciwa in his knowledge base instead of [CHECK] markers.

Not in 0.1: push / pull, VS Code, Chrome, monsterbrain, hosted service, Python/HTML adapters, the standalone engine. The design must not block them, though – especially review on results (Reviews happen on results, ... (DEC_REVIEW_ON_RESULTS)) and host apps (Host apps and the standalone engine).

Architecture¶

Every front end – the integrations as well as the agent skills – talks to the deciwa CLI and its core library, never to the files directly (The CLI is the master, with... (DEC_CLI_MASTER)). The CLI stores reviews in .deciwa/ inside the repository or, later, in the hosted service.

Repository¶

deciwa/
├── packages/            one package per part – see below
│   ├── core/            deciwa-core     model, .deciwa/ store, engine
│   ├── server/          deciwa-server   review server
│   ├── cli/             deciwa-cli      the deciwa command
│   ├── ui/              deciwa-ui       review overlay (JS/CSS)
│   ├── sphinx/          deciwa-sphinx   Sphinx extension
│   ├── client/          @danwos/deciwa-client   engine client for host apps (TypeScript)
│   └── monsterbrain/    deciwa-monsterbrain     the monsterbrain extension
├── docs/                these docs – product, integrations, decisions,
│                        technical details
├── .deciwa/             review data of these docs (config.toml: what must be approved)
├── mockups/             first clickable mock-up of the feedback UI, demo recorder
├── pyproject.toml       the uv workspace (all packages + docs tools)
└── uv.lock

deciwa-sphinx does not import deciwa-server: a static (offline) build needs no server. With deciwa serve, the server runs the Sphinx build, and the review UI in the pages talks to the server’s JSON API.

Rules:

  • Logic lives in deciwa-core only. The offline engine in deciwa-ui mirrors its rules for reviews without a server and must be kept in step.

  • deciwa-server and deciwa-cli are reused by every integration that reviews in a browser or calls the CLI.

  • An integration package depends on deciwa-core and, for a browser UI, on deciwa-ui – never on another integration.

Setting up¶

$ uv sync                          # all packages, editable, plus the docs tools
$ .venv/bin/deciwa serve           # the CLI from packages/cli

Using deciwa in another Sphinx project:

$ cd ~/workspace/deciwa/packages
$ uv pip install --python <project>/.venv/bin/python -e core -e server -e cli -e ui -e sphinx
